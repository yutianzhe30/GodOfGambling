# 技术实现方案 (Technical Plan)

## 1. 引擎与架构
- **引擎**：Godot 4.2 LTS (稳定版)。
- **维度**：完全 2D 开发。
- **语言**：GDScript。

## 2. 最小可行产品 (MVP) 阶段规划
严格限制开发范围，防止项目烂尾：
- **阶段 0 (核心验证)**：只做一桌普通的梭哈扑克，跑通发牌、跟注、开牌逻辑，无任何特异功能和剧情。
- **阶段 1 (技能引入)**：加入气场 (Aura) 条和 3 个基础特异功能，跑通玩家 vs AI 战斗模块。
- **阶段 2 (包装与 UI)**：加入像素风美术、UI 界面、CRT Shader 和背景音乐。
- **阶段 3 (流程串联)**：加入对话系统，串联 3 个 Boss 关卡，形成完整的游戏流程。

## 3. 技术难点简化方案
| 原设计难点                 | 简化后的替代方案                                                                                                                                   |
| :------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------- |
| **QTE 和 手速判定**        | **完全删除**。改为回合制点击发动技能，降低输入判定和防作弊等复杂开发，也更适合手游移植。                                                           |
| **扑克AI / 机器博弈**      | **放弃**复杂的胜率计算算法。改为状态机 (State Machine) 或硬编码逻辑：依据当前手牌等级（对子、顺子等）赋予AI一个“自信值”，结合随机数决定跟注/放弃。 |
| **多玩法混杂 (骰子/麻将)** | **放弃**。100% 聚焦梭哈扑克，共用同一套 UI 和发牌逻辑以节省时间。                                                                                  |
| **复杂 RPG 属性系统**      | **放弃**自由加点。改为固定的线性养成：打败Boss -> 气场上限+10，剧情解锁新特异功能。                                                                |

## 4. 第三方插件推荐
- **对话系统**：`Dialogue Manager` (Nathan Hoad) - 处理简单的游戏内文本。
- **存档系统**：直接使用 Godot 内置的 `ConfigFile` 或 `ResourceSaver` 存储进度和金钱，单机游戏初期暂不考虑强加密防修改。

## 总结
**少即是多 (Less is More)**。通过砍掉动作要素 (QTE)、多玩法和复杂的RPG树，目前的架构非常适合单人或小团队在 Godot 中快速实现，且依然能保留“港片+特异功能”的核心趣味。方案极具开发可行性。
