# 游戏核心概念 (Core Concepts)

## 核心愿景
《赌神》(God of Gambling) 是一款以80/90年代香港电影为背景的 2D 扑克策略RPG游戏。玩家扮演高进的关门弟子，通过不断挑战各地赌场，最终夺回"赌神"称号。

为了确保开发可行性，游戏将**极度聚焦于"梭哈 (Show Hand)"这一种扑克玩法**，并辅以轻量级的RPG技能（特异功能）系统。

## 核心玩法循环
1. **剧情推进**：通过简单的对话框交代背景和对手信息。
2. **赛前准备**：装备简单道具（如巧克力回复气力）。
3. **扑克对决**：进行带有"特异功能"的梭哈对局。
4. **资源结算**：赢得金钱和声望，解锁下一关或新技能。

## 精简后的RPG与技能系统
为了避免玩法过于复杂和数值失衡，取消复杂的QTE和多维属性，采用极简的"气场（Aura）"系统：
- **气场 (Aura) / 蓝量**：通过出牌、跟注或吃巧克力积攒。用于发动特异功能。
- **取消 QTE（单人）**：单人模式下所有特异功能改为**回合制发动**，只需消耗气场，无需拼手速。
- **删减多余小游戏**：初期**不开发**骰子和麻将，100%精力打磨梭哈的AI和演出效果。

## 视听风格
- **2D 像素风 (Pixel Art)**：降低美术成本，利用 Godot 的 Shader 实现复古 CRT 和霓虹色散效果。
- **演出重于操作**：重点放在发牌、开牌时的慢动作、特写和音效，还原电影的紧张感。
- **技能动画规范**：透视/情报类技能**不翻开牌面**，统一使用悬浮半透明HUD窗口或Shader高亮边框呈现情报，保留神秘感。

## 双人玩法

### 模式概述
- **在线双人玩法**（通过匹配码连接）与**本地单人玩法**完全兼容。
- 单人/双人共用同一套剧情结构和关卡，仅技能触发方式不同。

### 网络方案：WebSocket + 匹配码
- 玩家1创建房间 → 获得4位**匹配码**（如 `A7K3`）。
- 玩家2输入匹配码 → 双端通过轻量 WebSocket 信令服务器完成连接后P2P通信。
- 中继服务器仅负责配对，不运行游戏逻辑（Node.js 脚本，可免费部署）。
- **测试阶段**：开发期在同一电脑开两个Godot实例 + `localhost`；局域网测试；最终部署Railway/Render免费层做线上测试。

### 玩家角色分工
- **玩家1（主角）**：控制下注、弃牌、发动技能（消耗气场）。
- **玩家2（陈小刀）**：不直接下注，专职执行技能的"人力触发"部分（QTE / 协同输入 / 主观判断）。

### 叙事模式对比

| | 单人模式 | 双人模式 |
|---|---|---|
| **主角状态** | 天赋异禀，技能逐步成长 | 开局完全失忆 |
| **陈小刀角色** | 第一关导师NPC | 玩家2扮演的搭档 |
| **技能来源** | 主角自行成长解锁 | 小刀逐步"唤醒"主角记忆 |
| **叙事钩子** | 线性成长 | 每次成功使用技能触发一段回忆对话 |
| **技能G（变个3）** | 主角独自掌握 | 需玩家1+玩家2同时确认协同触发 |

### 双人模式最终Boss剧情节点
1. **强制失败**：剧情触发，主角必输一次（不可避免），气场清零。
2. **小刀救场**：玩家2单方面激活"金蝉脱壳"，保住底注，并将全部剩余气场传给玩家1。
3. **小刀退场**：叙事上小刀退出战场（告别/牺牲感），玩家2参与至此结束。
4. **主角独立决战**：主角获得一次性强化技能"**赌神附体**"（下一手牌必定为最强牌型），单独面对最终Boss，完成成长弧。

### QTE规范
- 所有双人QTE在**玩家2的屏幕**展示，不干扰玩家1的牌局视野。
- QTE结果（成功/失败/精准等级）通过 RPC 实时同步给玩家1的UI。
- QTE判定在玩家2本地完成，结果上传HOST，避免网络延迟影响判定公平性。
